# ARS Suite review — 2026-11-17

A review of the suite at `main` 74d3e2ba (v1.13.15 plus PRs #224–#226, not yet released), compared against `TODO.md` and the competitor
survey (TODO tier **2c**, from comparing the suite with N1MM+, DXLab, Log4OM, Wavelog, GridTracker and the portable loggers; commit
179035cf). There is no separate comparison document in the repo or in git history, so 2c is the comparison list used here, extended
with features those programs are known for and checked against this code.

**Method.** Read `TODO.md`, `README.md`, the CI workflows and the module layout. Searched the code for each competitor feature rather
than relying on the docs. Each finding below says where it was confirmed. Nothing here was checked on a running radio, printer or
second computer.

---

## 1. Summary

- **The code is in good shape.** About 56,000 lines of Java across five modules (ars-fx 38.9k, j-digi 9.2k, j-log-engine 5.3k,
  j-bridge 0.9k, j-log-common 0.9k) plus the installer (0.8k). There are 564 tests in ars-fx, all passing on Windows, and no
  TODO / FIXME markers in the main code.
- **The biggest risk is unverified features, not missing ones.** A large share of what `TODO.md` lists as built says "not yet tried",
  "not seen in the running app" or "not tried with a real rig / two computers". Several are features operators rely on during a
  contest (Cabrillo frequencies, the contest network, the N1MM broadcast). The recommendation is a **verification pass before more
  features**. Section 3 lists every check.
- **Four small problems turned up in the review** (section 2): a dead "+ Spot" control, CI that never runs tests on pull requests,
  passwords stored in plain text, and README claims that no longer match the code.
- **Against the competitors** the suite already covers most of what the 2c survey asked for. The remaining gaps are mainly what
  N1MM+ and DXLab users expect for serious contesting and DXing: SO2R, native WinKeyer, QSO audio recording, and spot alerts
  (section 5).

**Reading it.** The suite is broader than any one competitor: logger, contest program, mapping, satellites, digital modes, learning
and inventory in one app. Its gaps are depth gaps against the specialists: N1MM+ for serious contesting (SO2R, WinKeyer, QSO
recording), and DXLab / GridTracker for DX hunting (spot alerts, Club Log data). Its unique strengths (J-Learn, the Morse
Trainer, the Antenna Workshop, J-Vault, one config for everything) are the story to lead with.

## 6. Recommendations

1. **Verify before adding.** Spend the next sessions on sections 3a–3e. The ★ items come before the next contest you plan to
   enter, especially Cabrillo frequencies, the contest network and the N1MM broadcast. Every check that passes can drop its
   "not yet tried" text from `TODO.md`. Every one that fails is a bug found before an operator finds it.
2. **Close the review's small items in one PR:** the "+ Spot" control, tests in `build.yml`, the `release.yml` comment and the
   README corrections (2.1–2.3, 2.5). They are all small and remove real confusion.
3. **Decide the credential policy (2.4)** before the suite has many users. Plain-text passwords are the one finding with a security
   cost.
4. **Pick the audience for the next feature work:**
   - **Contesters** → WinKeyer, then QSO recording, then SO2R (largest).
   - **DXers** → spot alerts, then Club Log exceptions / Most Wanted.
   - **Everyday / portable operators** → Wavelog upload, the J-Vault estate document, then Info tab "Active now".
   Spot alerts and Wavelog upload are the cheapest wins with the widest reach.
5. **Keep the release cadence honest:** with tests in PR builds (2.2), the nightly's green-build gate also means "tests passed",
   which it does not today.
6. **Tidy `TODO.md` (2.6)** so it lists only open work, and move this review's new items (4b) into it once you have decided which
   to take on.
