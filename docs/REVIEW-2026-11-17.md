# ARS Suite review — 2026-11-17

A review of the suite at `main` 74d3e2ba (v1.13.15 plus PRs #224–#226, not yet released), compared against `TODO.md` and the competitor
survey (TODO tier **2c**, from comparing the suite with N1MM+, DXLab, Log4OM, Wavelog, GridTracker and the portable loggers; commit
179035cf). There is no separate comparison document in the repo or in git history, so 2c is the comparison list used here, extended
with features those programs are known for and checked against this code.

**Updated at the end of the day** (`main` 0df0505a): PRs #227–#252 were merged after the review was written. They closed every
section-2 item, built several section-4b items and fixed further bugs found by probing the code. Each section below is marked, and
**section 8** lists every change with its PR. None of it is released yet: v1.13.16 is waiting for the nightly or a manual release.

**Method.** Read `TODO.md`, `README.md`, the CI workflows and the module layout. Searched the code for each competitor feature rather
than relying on the docs. Each finding below says where it was confirmed. Nothing here was checked on a running radio, printer or
second computer.

---

## 1. Summary

- **The code is in good shape.** About 56,000 lines of Java across five modules (ars-fx 38.9k, j-digi 9.2k, j-log-engine 5.3k,
  j-bridge 0.9k, j-log-common 0.9k) plus the installer (0.8k). There are 564 tests in ars-fx, all passing on Windows, and no
  TODO / FIXME markers in the main code.
- **The biggest risk is unverified features, not missing ones.** A large share of what `TODO.md` lists as built says "not yet tried",
  "not seen in the running app" or "not tried with a real rig / two computers". Several are features operators rely on during a
  contest (Cabrillo frequencies, the contest network, the N1MM broadcast). The recommendation is a **verification pass before more
  features**. Section 3 lists every check.
- **Four small problems turned up in the review** (section 2): a dead "+ Spot" control, CI that never runs tests on pull requests,
  passwords stored in plain text, and README claims that no longer match the code.
- **Against the competitors** the suite already covers most of what the 2c survey asked for. The remaining gaps are mainly what
  N1MM+ and DXLab users expect for serious contesting and DXing: SO2R, native WinKeyer, QSO audio recording, and spot alerts
  (section 5).
- **State QSO parties** (section 7, added later the same day): the engine now scores the entrant's power, station category and own
  counties, and North Carolina follows its 2027 rules. What is left needs source material (official county lists, current rules
  from several sponsors) more than code, and the new rules have not been tried on the running contest page.
- **End of day:** all of section 2 is fixed (#227). Spot alerts, Wavelog upload, Club Log Most Wanted and the J-Vault estate
  document are built. Probing the code turned up and fixed 14 more bugs, several of which would have reached sponsors or QSL
  services: Cabrillo modes, ADIF fields lost on import, frequencies typed in kHz, wrong DXCC entities in contest scoring, and dropped
  cluster spots (section 8). There are new checks for these in 3a.

## 7. State QSO parties

The suite carries 46 QSO-party definitions (`j-log-engine/src/main/resources/com/jlog/plugins/*_qso_party.json`) scored by one
configurable engine (`ContestScorer`, `multiplierType: "qso_party"`). The county lists live in
`j-log-engine/src/main/resources/com/jlog/counties/`. Each definition's `scoreFormula` note records the rules as checked, and
what is *not* scored.

### 7a. Built 2026-11-17 (merged in #228; follow-ups #230–#232, #234, #235)

- **Entry categories reach the scorer.** `StationContext` now carries the entry's Cabrillo CATEGORY-POWER and CATEGORY-STATION from
  Setup ▸ Contest.
- **New per-definition rules** (`scoringRules.qsoParty`, all opt-in; with none set a score is unchanged):

  | Key | What it does | Used by |
  |---|---|---|
  | `powerMultiplier` | × (QSO points × multipliers) by CATEGORY-POWER; bonuses added after | DE, FL, KY, NM, NE, MD-DC, PA (QRP ×2), VT, WI |
  | `stationMultiplier` | the same, by CATEGORY-STATION | MD-DC (ROVER 4, PORTABLE 3, MOBILE 2, FIXED 1) |
  | `pointsByPower` | every scoring QSO is worth N | ID (QRP = 5) |
  | `activationBonus` | per own county (sent county logged on each QSO) with N QSOs (and optionally N different stations): points, or that county as a multiplier | AR, CO, NM, OK, PA, TN, TX, WI, WV, NS, ON, QC, NC; MO as a multiplier |
  | `ownCountyDupe` | the sent county is part of the dupe key: a mobile re-works everyone from a new county | DE, KY, FL, NE, MD-DC, PA, ID, AR, OK, TN, TX, WV, ON, QC, MO, NC |
  | `homeCountyMult` | an in-state entrant's own counties are free multipliers | NC |
  | `bonusStationsBelow50Mhz` | bonus stations count below 50 MHz only | WI (W9FK) |
  | `electronicLogBonus` | post-multiply bonus for an electronic log | DE 50, KY 100, MO 100 |
  | `timeWindowBonus` | +N per QSO on given bands in UTC windows, capped | MO (40 / 80 m, Sat and Sun 1400–2000 UTC, +1, cap 250) |
  | `bonusSweep` | +N once every one of a set of calls is worked | NC (HIKENC: +200) |

- **Rules re-read from the sponsors today:**
  - **Missouri** ([2026 rules PDF](https://www.w0ma.org/mo_qso_party/results/thisyear/moqp-2026-rules-final.pdf)): the time-window point, the e-log bonus and the 50-QSO mobile county multiplier.
  - **North Carolina** ([rules page](https://ncqsoparty.org/rules/), [2027 PDF](https://ncqsoparty.org/wp-content/uploads/2026/11/Rules_2027_261115a.pdf), updated 2026-11-07): moved to the 2027 rules. The rarest-counties ×10 rule is gone; own counties are free multipliers; HIKENC N4H/I/K/E/N/C are 50 each plus 200 for all six; mobiles and portables get +100 per county activated.
- **Values for the other parties** came from each definition's November-2026 notes. VT's power tiers and KY's bonus came from their 2027 rules or draft, and NE's from the 2025 summary sheet (7d).
