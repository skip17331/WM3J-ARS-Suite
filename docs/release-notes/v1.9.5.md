## WM3J ARS Suite v1.9.5

The local CW skimmer works again, J-Digi follows more of J-Hub's settings, RTS/DTR push-to-talk now works, and the
hardware guide matches the real screens.

### New
- **Local CW skimmer.** J-Digi can listen to the CW on the rig's audio and post the callsigns it decodes to the shared
  spot list, alongside DX cluster and RBN spots. Turn it on with **J-Hub ▸ Data ▸ Local CW skimmer**. Spots appear
  under the spotter `<your call>-SKM`, at the dial frequency plus the tone. The CW decoder is least reliable at about
  15 wpm and above, where letters can run together, so expect few callsigns from fast contest CW.
- **J-Digi CW speed and keyer follow J-Hub.** The CW speed set in J-Hub's Transmit section now sets J-Digi's speed. A
  new **J-Digi CW keyer** choice there picks **Audio** (a tone through the sound card) or **Rig keyer** (keying through
  the rig).
- **RTS and DTR push-to-talk.** Choosing RTS or DTR as the **PTT method** now passes the PTT type and serial port to
  `rigctld` when J-Hub starts it. A `rigctld` that J-Hub started is restarted when its settings change. One you started
  yourself is never touched.

### Fixed
- **J-Bridge country and distance describe the transmitting station.** On a message such as `N0CALL ZS6AA -12`, the
  country, continent and distance used to describe the station being called (`N0CALL`) instead of the one sending
  (`ZS6AA`). They now follow the sender. The callsign column is unchanged.

### Documentation
- **Hardware guide rewritten** against the real J-Hub pages (Hardware ▸ Rig control, Rotor control, Amplifier, Antenna
  switch). It no longer describes a web page, a Save button or model dropdowns that do not exist, and it says that
  "Start rigctld for me" is off by default. J-Hub does not control antenna switches: that page only records the
  switch's model, connection and port names, and the guide now says so.
- `design/ars-suite/HANDOFF.md` is now short reference notes instead of a build task list.

### Housekeeping
- Tests no longer read or write your real Java preferences.
