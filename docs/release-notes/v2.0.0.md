## WM3J ARS Suite v2.0.0

**Contest logging has moved out of the suite into its own program, ARS Contest.** The suite is now the whole shack with an everyday log, and it can be installed with no build.

### Changed
- **Contest mode is gone from the suite, on purpose.** Running a contest is a different job from running a shack, and doing it justice takes a program built around it: its own screens and keyboard flow, each sponsor's scoring rules for 86 contests, a log per contest, several stations sharing one log, and a Cabrillo file the sponsor accepts. Inside the suite it had to share screens, Setup pages, settings and a release cycle with every other module, so it could never be given the focus it deserved. As **[ARS Contest](https://github.com/skip17331/WM3J-Contest-Suite)** it can be built and released at the pace of contests. The reasoning, and what is where, is in the README ("Contesting — its own program").
  - Removed from the suite: the contest page and custom cockpit, the contest network, the N1MM+ broadcast, Cabrillo export, Super Check Partial, the 86 contest definitions, the contest databases, and the Setup pages that went with them (*Cabrillo & entry*, *Contest network*, *N1MM broadcast*, the contest databases list).
  - **J-Log** is the everyday log: the New QSO form, recent log, the log browser (now just the normal log), awards, uploads, QSL labels, the translator. The dock's J-Log entry opens it; the old `logc` module id is gone.
  - **Kept:** the Info page's contest *calendar*, the country files, call history (it places stations on J-Map), the translator and the macro engine.
  - **Your old contest logs were not touched.** `~/.j-log/contest.db` and `~/.j-log/contest-logs/` stay on disk and nothing in the suite reads them. To open one in ARS Contest, copy the database file (with any `-wal` / `-shm` beside it) into `~/.ars-contest/contest-logs/` under a new name while both programs are closed. `~/.j-hub/scp/` is also left over and can be deleted.
  - ARS Contest installs beside the suite: its own folder (`~/.ars-contest`), hub port (8091), shortcuts and installer. The first time it runs it copies your station, rig, rotor, amplifier, transmit and cluster settings from the suite.
- **Macros:** the `{EXCH}` and `{NR}` tags, which only the contest page supplied, are gone. Every other tag works as before.
- **J-Map:** the Sweepstakes-sections overlay is gone (it only made sense with contest scoring). States / provinces keeps its saved on / off setting.
- **Version:** 2.0.0 for the app, the installer and the libraries.

### New
- **Install without building.** Download `j-installer-<version>.jar` from a release and run `java -jar` on it: it fetches the right app jar for your computer, checks it against the SHA-256 GitHub publishes (a file that does not match is not installed), and adds the same menu shortcuts as the source install. Needs only Java 21; never touches your settings, logs or databases. Re-running it upgrades. INSTALL.md, Option A2.

### Fixed
- **The background hub now runs on the same home folder as the window that starts it.** It used to be started with the real `~/.j-hub` whatever the window used, which mattered only for a run on another home (a dev run on a scratch folder copied the real call, grid and position into it). No change for a normal install.

### Not yet tried
- The no-build installer on Windows and macOS (it was run on Linux, against the real release from github.com, and the app's updater accepts the layout it makes).
- ARS Contest attached to this suite's hub in a real session with a radio (it was run against stand-ins).
- The full log browser, Awards and Translator windows after the contest code was removed: they open without errors, but their contents were not looked at.
