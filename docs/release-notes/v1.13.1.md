## WM3J ARS Suite v1.13.1

A rotor release: an az/el rotator now follows a satellite in elevation as well as azimuth, a rotator that turns 450° no longer unwinds a whole turn mid-pass, and you can have a second rotor just for satellites. All of it is switched off or unchanged until you turn it on, so an existing rotor setup behaves exactly as before.

### New
- **Elevation tracking.** J-Sat's tracking used to send only an azimuth. With the new **Elevation rotor (az/el)** switch (J-Hub > Hardware > Rotor control) a pass points the elevation at the satellite as well (0-90°), and the dead-band applies to both axes. Leave it off for an azimuth-only rotator such as an HF beam's: it is then never sent an elevation.
- **450° rotators.** The **Overlap / wrap** setting is now real. Set **Rotor range** to 450° and say where it overlaps (North = travel 0 to 450°, South = -180 to +270°): every move goes to whichever of the two angles for the bearing is nearer to where the rotor is, so a pass that crosses the overlap carries on past 360° instead of unwinding. The range defaults to 360°, so a rotator that turns once is unchanged.
- **A second, satellite rotor.** J-Hub can now drive two rotors, each with its own `rotctld`: the main one (an HF beam's, say) and an optional **satellite rotor** (an az/el rotator on the satellite antenna). Turn it on under **Satellite rotor** on the rotor page, with its own connection (on its own port, 4534 by default), range, overlap, park and elevation settings; **Start rotctld for me** can start its daemon. J-Sat's tracking drives it; spot clicks, the beam presets, Park and the J-Map beam stay on the main rotor. It has its own **Satellite rotor** panel in J-Sat (compass, azimuth and elevation, CCW / Stop / CW, Park); the other screens show only the main rotor. With it off, J-Sat uses the main rotor as before. A homebrew az/el controller that expects EasyComm needs a Hamlib model that speaks it: pick the **Easycomm** entry from `rotctl --list`.

### Fixed
- The rotor move command was written with the computer's regional number format, so a comma-decimal system would have sent `P 123,4 45,0` to `rotctld`; it now always uses a decimal point.

### Not yet tried
- Tested against stand-in rotctld servers and in the running app, but **not on a real rotator** (including EasyComm hardware), and not with J-Sat tracking a live pass. Please watch the first moves.
