## 2c. Next — gaps found in the competitor survey
From comparing the suite with N1MM+, DXLab, Log4OM, Wavelog, GridTracker and the portable loggers. We are working on these.
- [ ] **S** Super Check Partial and the band map: built, including the worked tick on SCP chips (contest and normal log), a SCP strip in the normal log, click-to-tune on the band map ruler, band-plan segment shading (CW / data / phone) and a blue label for spots from your own skimmer. Left: try the band map features with a rig; decide whether a separate band map is wanted on the contest page (it already shows the cluster card, with its Map / List switch, beside the entry).
- [ ] **S** **Phone-friendly web client** is built (`WebClientServer`, J-Hub > Data > Phone web client; off by default): the hub serves one responsive page and a token-protected JSON interface for the station and rig state, DX spots with the band-open estimate, the recent log and posting a QSO. QSOs typed without a signal wait on the phone and are sent with their real times when the network returns; an id on each stops a retry being logged twice. Tuning the rig from the phone is a second switch, off by default. **The page has been parsed but not yet opened in a browser or on a phone** - try the log form, the offline queue (switch the phone to airplane mode, log, switch back), the spots tab and the token entry. Left: plain HTTP only, so the page does not load offline (a service worker needs HTTPS); reaching it from outside your network is a job for a VPN, not built in; the hub needs a full JDK (the built-in `jdk.httpserver` module).
- [ ] **M** Our own propagation estimate, stage 1 is built (`Propagation`, `PathPropagationView`, in the Propagation drawer): from the solar flux, sunspot number and K index the app already pulls, a MUF and LUF for the path from your station to a call or prefix (the last spot you clicked), shown as a 24-hour by band grid; it says on the panel that it is an estimate. It is a simple model (secant-law MUF from a flux-based foF2, D-layer absorption for the LUF). The spot card has a **Path now** and a **Best time** line, the J-Map dots fade when the band is probably closed and get a green ring when it is likely open (filter switch "Path now"), and the spot lists show a green / amber / grey dot. **Those screens are not yet looked at in the running app.** It now scores itself (`PropagationCheck`): every cluster spot of 1,000 km or more is a path that was open, so the answer for that path is tallied per band and kept between sessions, and the panel shows the running result (click it to start again). It can only count misses, not false alarms. **Next: leave it running for a few weeks and read the numbers** - the weakest bands say where to improve it. Not built, because they need data we do not have or licence: the ITU-R P.533 foF2 / M3000 coefficient maps (check their licence), sporadic E, grey-line enhancement, the winter anomaly, polar paths, and the operator's power and antennas; add them one at a time and watch the check.
- [ ] **S** N1MM-compatible UDP broadcast is built (`N1mm` messages, `N1mmBroadcast` sender, `N1mmListener`; Setup > Data, off by default): contacts added / edited / erased, lookups, radio info, app info, (optional) score and spots, the normal log's QSOs, an address of its own for each kind of message, the "All Computers" re-send of contacts that arrive over the contest network (off), a RUN / S&P switch on the contest page that goes out as RadioInfo `IsRunning` and contact `IsRunQSO`, and the inbound set-frequency command on UDP 13064 (off; this computer only unless you allow the network, then private addresses only and only the senders you name; radio 1 only, rig connected, not transmitting, inside an amateur band). Check it against a real receiver (GridTracker, Log4OM) and a real N1MM+ capture - the format was written from N1MM+'s document, whose own examples have typos, and the document names neither the unit of a spot's frequency (written in kHz), nor of the set-frequency request (read as kHz), nor the values of `IsRunQSO` (1 = run is an assumption). Still open: rotator messages (port 12040; the document shows the packet only as a picture and says it is not XML).
- [ ] **L** Network mode (`com.ars.fx.net`, Setup > Data > Contest network, a strip on the contest page): one station hosts and the others join; every station keeps a full copy of the contest log, so one that loses the host keeps logging and catches up on reconnecting. QSOs have a global id and a version; the later change wins; points and dupe flags are worked out at each station; a shared key (HMAC handshake) keeps stray devices out. Since stage 1: **everything after the handshake is encrypted** (AES-GCM, a key per connection); a station finds the host by itself if the address is left blank (the host announces its name and port, never the key); **the host hands out serial numbers** so two stations never take the same one (a station that cannot reach the host uses its own count); **chat** to all stations; each station reports **Run or S&P**, with a warning when two run on the same band; the strip shows **each operator's QSOs and last-hour rate**. **Not tried on two real computers yet** - only on loopback in tests; try it with two real computers, including pulling a cable. Still open: a standby host if the host dies (needs the stations to know each other's addresses and agree who takes over); QTCs and the normal log are not shared (only the contest log; QTCs would need ids and versions like QSOs); private messages and scheduled skeds (chat is to everyone); roles beyond the run warning (a multipliers station that sees only what is still needed); a chat line recorded and replayed within one connection would show twice.
