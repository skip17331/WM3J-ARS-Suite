## 2c. Next — gaps found in the competitor survey
From comparing the suite with N1MM+, DXLab, Log4OM, Wavelog, GridTracker and the portable loggers. We are working on these.
- [ ] **S** Super Check Partial and the band map: built, including the worked tick on SCP chips (contest and normal log), a SCP strip in the normal log, click-to-tune on the band map ruler, band-plan segment shading (CW / data / phone) and a blue label for spots from your own skimmer. Left: the DX and Sweepstakes call lists (`MASTERDX` / `MASTERSS`; no stable source checked); the contest page already shows the cluster card, with its Map / List switch, beside the entry - decide whether a separate band map is wanted there; try the new band map features with a rig.
- [ ] **L** **Phone-friendly web client** for the hub, for portable (POTA / SOTA) logging and shack monitoring without a native app: a responsive page served by the hub (the WebSocket link already exists) with QSO entry, spots, rig and rotor status; keep working offline in the field and sync when back on the network. Needs a login or token on the LAN and a decision on how it is reached from outside.
- [ ] **M** Our own propagation estimate, stage 1 is built (`Propagation`, `PathPropagationView`, in the Propagation drawer): from the solar flux, sunspot number and K index the app already pulls, a MUF and LUF for the path from your station to a call or prefix (the last spot you clicked), shown as a 24-hour by band grid; it says on the panel that it is an estimate. It is a simple model (secant-law MUF from a flux-based foF2, D-layer absorption for the LUF) and it is **not checked against measured data or VOACAP** - compare it with real openings or a VOACAP run before trusting it, especially on long multi-hop paths, which are its weakest part. Next stages: refine toward ITU-R P.533, and the foF2 / M3000 coefficient maps that need (static data files; check their licence), sporadic E, grey-line enhancement, the winter anomaly, polar paths, and the operator's power and antennas. The spot card on J-Map has a **Path now** line (likely open / marginal / probably closed, with MUF and LUF) and a **Best time** line (when it is worth trying in the next 24 hours); the J-Map dots fade when the band is probably closed and get a green ring when it is likely open (switch: J-Map filters, "Path now"), and the spot lists (J-Map, dashboard, J-Log) show a green / amber / grey dot. **These screens are not yet looked at in the running app** - check the dots, ring and list chips against what you hear on the bands. Still to do: a wider study of the estimate against real openings.
- [ ] **S** N1MM-compatible UDP broadcast is built (`N1mm` messages, `N1mmBroadcast` sender, `N1mmListener`; Setup > Data, off by default): contacts added / edited / erased, lookups, radio info, app info, (optional) score and spots, the normal log's QSOs, an address of its own for each kind of message, the "All Computers" re-send of contacts that arrive over the contest network (off), and the inbound set-frequency command on UDP 13064 (off; this computer only; acts for radio 1 only, with the rig connected, not transmitting and inside an amateur band). Check it against a real receiver (GridTracker, Log4OM) and a real N1MM+ capture - the format was written from N1MM+'s document, whose own examples have typos, and the document names neither the unit of a spot's frequency (written in kHz) nor of the set-frequency request (read as kHz). Still open: rotator messages (port 12040; the document shows the packet only as a picture and says it is not XML), run / S&P (`IsRunQSO`; the document gives no values and we have no Run / S&P switch yet), and the set-frequency listener on the LAN (it hears this computer only).
- [ ] **L** Network mode, stage 1 is built (`com.ars.fx.net`, Setup > Data > Contest network, a strip on the contest page): one station hosts and the others join; every station keeps a full copy of the contest log, so one that loses the host keeps logging and catches up on reconnecting. QSOs have a global id and a version; adds, edits and erases are sent at once and the later change wins; points and dupe flags are worked out at each station from the merged log; a shared key (HMAC handshake) keeps stray devices out; the strip shows who is joined and what each is on, and warns of a station in another contest or on the same band and mode. **Not tried on two real computers yet** - only on loopback in tests. Still open: chat and skeds; per-operator stats; multi-multi roles (one run station per band, multipliers station); serial numbers (two stations can take the same next number at the same instant); encryption of the LAN traffic (only the key is protected); finding the host automatically (mDNS) instead of typing its address; a standby host if the host dies; QTCs and the normal log are not shared (only the contest log).
