# FT8 / FT4

> **Advanced callout convention:** sections or paragraphs intended for Extra-class / engineering depth are marked with a blockquote starting `> ⚙️ **Advanced —**`. Simple-mode renderers can hide these; advanced-mode renderers show them inline.

## What it is

FT8 and FT4 are weak-signal digital QSO modes designed by Joe Taylor (K1JT) and Steve Franke (K9AN). Both exchange short, fixed-format messages (callsigns, signal reports, grid squares) within strictly-timed slots. Released in 2017 (FT8) and 2019 (FT4), they have become the dominant HF DXing modes — by 2024 most days more FT8 QSOs happen than all other modes combined.

FT8 trades speed for sensitivity: a full QSO takes about 90 seconds, but it works at signal levels where the operator can't even hear the carrier (~−24 dB SNR in 2.5 kHz reference bandwidth). FT4 is a faster, less-sensitive variant for contesting (~−17 dB SNR, half the slot length).

## How it works

| Property | FT8 | FT4 |
|----------|-----|-----|
| Modulation | 8-FSK (8 tones) | 4-GFSK (4 tones, Gaussian-shaped) |
| Symbol rate | 6.25 baud | 23.4 baud |
| Tone spacing | 6.25 Hz | 23.4 Hz |
| Total bandwidth | 50 Hz | 90 Hz |
| Slot length | 15 seconds | 7.5 seconds |
| FEC | LDPC (174,91) | LDPC (174,91) |
| Message size | 77 information bits | 77 information bits |
| Transmit fraction of slot | 12.6 sec / 15 sec | 4.5 sec / 7.5 sec |
| Decoder threshold | ~−24 dB SNR | ~−17 dB SNR |
| Clock tolerance | ±1 second | ±0.5 second |

Both modes pack everything (callsign 1, callsign 2, grid / report) into 77 bits. The 77 bits are then expanded by an LDPC error-correcting code to 174 bits, mapped onto FSK symbols, and bracketed by **Costas arrays** (sync patterns) at the start, middle, and end of the message. The decoder uses the Costas arrays to find the signal in time and frequency, then runs LDPC decoding to recover the message.

The fixed message format is what gives FT8 / FT4 their efficiency: there's no free-form text to encode, just a small set of QSO primitives (CQ + grid, callsign + grid, callsign + signal report, RR73, 73). Outside that grammar, very little can be communicated — which is the design trade.

> ⚙️ **Advanced —** The 77-bit payload supports multiple message types: standard CQ + grid, contest-specific (RTTY Roundup, ARRL Field Day, NA VHF Sprint), DXpedition fox/hound mode, EU VHF compact format. Each is selected by a 3-bit type field. The receiver tries all decodings; the most likely one wins.

## Why use it

- **Weak-signal performance.** FT8 decodes signals 10 dB below the ear's threshold for CW. A 5 W QRP signal on a wire dipole works DX every day.
- **Low duty cycle on the operator.** You click the next CQ, the software handles the QSO. Compatible with running errands, dinner, and helping with homework.
- **Big DX hours saver.** The mode is so efficient that DXpeditions complete thousands of QSOs per day — much faster than the same activations on SSB or CW.
- **Standardized exchange.** No "what was your name again?" — the QSO is locked to a small grammar so software can handle the entire transaction.
- **No special equipment.** Any HF rig + computer + sound interface; no amplifier needed.

When to skip it: if you want a conversation, FT8 is the wrong tool — there's no rag-chew possible. Use JS8Call (§19-04) or PSK31 (§19-03) instead.

## Operating

**Software:** WSJT-X (the standard) or JTDX, MSHV (forks with different decoders).

**US calling frequencies (USB dial):**

| Band | FT8 | FT4 |
|------|-----|-----|
| 160m | 1.840 | — |
| 80m | 3.573 | 3.575 |
| 60m | 5.357 | — |
| 40m | 7.074 | 7.0475 |
| 30m | 10.136 | 10.140 |
| 20m | 14.074 | 14.080 |
| 17m | 18.100 | 18.104 |
| 15m | 21.074 | 21.140 |
| 12m | 24.915 | 24.919 |
| 10m | 28.074 | 28.180 |
| 6m | 50.313 | 50.318 |
| 2m | 144.174 | — |

The dial frequency is the *USB carrier*; signals appear in the 200 Hz to 3000 Hz audio passband above that. WSJT-X shows them on a waterfall.

**A typical QSO sequence:**

```
TX1 (you):     CQ K1ABC FN42
TX2 (them):    K1ABC W2DEF FN31
TX3 (you):     W2DEF K1ABC -10
TX4 (them):    K1ABC W2DEF R-08
TX5 (you):     W2DEF K1ABC RR73
TX6 (them):    K1ABC W2DEF 73        (optional)
```

Each transmission is one slot. A complete QSO is 4 to 6 slots, or 60 to 90 seconds. WSJT-X automates this — you click a station on the waterfall and the software walks the sequence.

**Power level:** 5–25 W is plenty for DX. Running 100 W is rude on a crowded band; running 1500 W is internationally infamous.

**Audio level setup:** WSJT-X transmit power slider should leave the rig's ALC light **just barely** lit (or off entirely). Receive should keep the green WSJT-X meter at 30–40 dB. Over-driving the rig's audio causes inter-modulation that splatters across the band.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| WSJT-X shows "decoded 0 in 0 sec" repeatedly | Computer clock not synced | Enable OS NTP; check via `ntpdate -q time.google.com` (Linux) or w32tm /query (Windows) |
| Some signals decode, others don't, on a busy band | Signal too strong (clipping) | Reduce RF gain or RX audio; the WSJT-X meter should show 30–40 dB max |
| You're calling CQ but nobody answers | Audio not making it to the antenna | Check ALC light; verify you can be heard on a SDR receiver (e.g. WebSDR.org); confirm dial frequency |
| Calls reach you but your "CQ K1ABC" doesn't appear on others' waterfalls | Transmit audio level wrong (likely too low) | Increase WSJT-X power slider until ALC just lights; verify on a remote SDR |
| Distorted signal in waterfall (vertical lines from your station) | Over-driven audio causing IMD | Reduce audio level; check rig's ALC reading during TX |
| Cannot answer a station — clicking does nothing | Wrong audio routing | Check WSJT-X "Sound" settings; rig's audio device must be both input and output |
| Frequency shows offset (e.g. 14.075 instead of 14.074) | Rig's USB pitch offset | Check rig's USB-mode menu (Carrier Point Frequency or BFO offset); should be 0 |
| Slow / dropped decodes on a fast computer | Antivirus scanning the working directory | Exclude WSJT-X folder from real-time scanning |
| TX timeline starts late | Computer is slow to start audio output | In WSJT-X, set "Tx delay" to 200–500 ms |
| The band is clear, but FT4 still doesn't decode | FT4 expects different audio range than FT8 | FT4 uses a different waterfall position; check WSJT-X's mode-specific window |
