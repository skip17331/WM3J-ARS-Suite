# RTTY — Radioteletype

> **Advanced callout convention:** sections or paragraphs intended for Extra-class / engineering depth are marked with a blockquote starting `> **Advanced —**`. Simple-mode renderers can hide these; advanced-mode renderers show them inline.

## What it is

RTTY is the original ham digital mode — directly descended from 1940s commercial teleprinters. It transmits text using a 5-bit Baudot character set as two-tone FSK ("mark" and "space"). Mechanical Teletype machines printed RTTY for decades; today everyone uses software (MMTTY, fldigi) but the on-air signal is identical.

Despite being 80 years old, RTTY is still alive in two communities: **DX contesters** (CQ WW RTTY, ARRL RTTY Roundup, BARTG, SARTG) and **digital-historians**. It's the easiest digital mode to copy by ear — fading in and out, you can still hear the chirping mark/space tones — which is part of its charm.

## How it works

| Property | Value |
|----------|-------|
| Modulation | 2-tone FSK (frequency-shift keying) |
| Symbol rate (amateur standard) | 45.45 baud |
| Tones — mark / space shift | 170 Hz (amateur) or 850 Hz (commercial) |
| Bits per character | 5 (Baudot) |
| Total characters in alphabet | 32 letters + 32 figures (shifted) |
| Bandwidth | ~250 Hz (with 170 Hz shift) |
| FEC | None |
| Error detection | None (you read garbage and ignore it) |
| Sync | Per-character start/stop bits (1 / 1.5 bits) |
| Clock tolerance | None — continuously synchronized |

Each character is **5 information bits** + **1 start bit** + **1.5 stop bits** = 7.5 bits per character, at 45.45 baud → **6.06 characters per second** = **~60 WPM**. There's no "letters" / "numbers" — Baudot uses two **shift modes**, like an old typewriter. A "letters shift" character switches the decoder to the letter alphabet; a "figures shift" character switches to digits and punctuation. If a shift character is corrupted, the next several characters will print as the wrong alphabet.

```
Mark tone   ─────╮     ╭────╮      ╭──── ...
                 │     │    │      │
Space tone       ╰─────╯    ╰──────╯
                 ↑                  ↑
              start              stop
```

Mark = idle / "1" / higher tone (typically 2125 Hz in audio).
Space = "0" / lower tone (typically 1955 Hz with 170 Hz shift, 1275 Hz with 850 Hz shift).

**FSK vs. AFSK.** Two ways to generate the same signal:

- **AFSK**: computer plays mark/space audio tones into the rig's mic input; rig is in SSB mode. Most common today. Software-controlled.
- **FSK**: rig's "FSK" or "RTTY" mode keys the carrier directly via a serial line or hardware key. Slightly cleaner spectrum (no SSB filter rounding), but requires rig support and an FSK-capable interface.

For a beginner: AFSK is easier and works on every rig. FSK is for serious contesters.

> **Advanced —** RTTY-FSK timing is more accurate than AFSK because the carrier is keyed directly without an SSB filter in the path. SSB filters (typically 2.4 kHz wide) shape the AFSK signal slightly, smearing tone transitions. On crowded contest bands, FSK signals are typically 6–10 dB cleaner than AFSK — visible as narrower spectral footprints.

## Why use it

- **Contests.** Major RTTY contests (CQ WW RTTY, RTTY Roundup, BARTG) attract thousands of participants. Highly competitive. Logging software (N1MM+, WriteLog) is mature.
- **Easy to copy through fading.** The mark/space chirp is audible even when SSB is unintelligible. Operators with experience can copy 50% of RTTY by ear.
- **No clock requirements.** Unlike FT8, RTTY doesn't care about your computer's time.
- **Compatible with any HF rig.** Works on any rig with USB or LSB audio.
- **Historical / sentimental.** Some operators love the connection to commercial-radio history. Old Teletype machines still run on bands like 14.080 MHz.

When to skip it: if you're after weak-signal DX (use FT8), conversational chat (PSK31 / JS8Call), or contemporary contesting outside the RTTY-specific events (CW or SSB).

## Operating

**Software:** MMTTY (Win, classic) or fldigi (cross-platform, free). N1MM+ for contesting; integrates a built-in RTTY decoder.

**US calling frequencies:**

| Band | Activity center (USB dial) |
|------|---------------------------:|
| 80m | 3.580–3.600 |
| 40m | 7.040–7.060 |
| 30m | 10.140 |
| 20m | 14.080–14.100 |
| 17m | 18.105 |
| 15m | 21.080–21.100 |
| 10m | 28.080–28.100 |

For SSB-mode AFSK: tune the rig to about 1 kHz below the actual signal in USB, so the audio tones land near 2125 Hz mark and 1955 Hz space. Most software has an "RTTY tune" function that helps.

**A typical RTTY DX QSO:**

```
TX: CQ CQ CQ DE K1ABC K1ABC K1ABC K
RX: K1ABC DE W2DEF W2DEF W2DEF K
TX: W2DEF DE K1ABC = UR RST 599 599 = QTH BOSTON BOSTON = NAME JOHN JOHN K
RX: K1ABC DE W2DEF = UR RST 599 599 = QTH PHILA PHILA = NAME MIKE MIKE K
TX: W2DEF DE K1ABC TNX QSO ES 73 K
```

Repetitions are common — RTTY has no error correction, and a missed character means a failed copy. By repeating each piece of info 2–3 times you ensure the other operator catches it through fading.

**A contest RTTY exchange** is much shorter — typically callsign + signal report + state/zone, repeated once. The contest software auto-generates the exchange and logs it.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| All decoded text is `RYRYRYRY` | This is the standard tuning indicator (R and Y in Baudot are alternating mark/space) — someone is testing or calling. Not an error. | — |
| Decoded text is mostly garbage | Wrong shift (170 vs. 850 Hz) or wrong sideband | Set software to 170 Hz shift; ensure rig is on USB (US/EU convention) |
| Mark and space are reversed | "Reverse" mode — mark and space are swapped | Toggle the Reverse / Normal button in the software |
| Decoder stuck in figures mode | Letters-shift character was corrupted | Send your own letters-shift to reset; or wait for the other station to do so |
| Audio looks fine but no characters appear | Decoder threshold too high | Lower the squelch / threshold in the software (fldigi has a slider) |
| Random spurious characters during RX | Decoder triggering on noise | Increase squelch; verify shift; tune up/down to find the actual signal |
| Sent text doesn't appear on remote SDRs | Audio not making it through ALC | Check ALC light; ensure rig is in SSB-USB; check audio level (50–80% is typical) |
| Cannot transmit FSK with AFSK software | These are different modes | Use AFSK in SSB-USB mode if your software is AFSK; rig must support FSK / RTTY mode for FSK keying |
| Spectrum analyzer shows splatter when transmitting | Audio over-driven | Turn down PC audio output; ensure ALC is barely lit |
| Different software shows different decoded text | One has mark/space wrong, or shift wrong | Cross-reference; also check that you're not decoding two overlapping signals |
