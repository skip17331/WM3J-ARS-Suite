# FSQ — Fast Simple QSO

> **Advanced callout convention:** sections or paragraphs intended for Extra-class / engineering depth are marked with a blockquote starting `> **Advanced —**`. Simple-mode renderers can hide these; advanced-mode renderers show them inline.

## What it is

FSQ (Fast Simple QSO) is a 33-tone MFSK mode designed by Murray Greenman (ZL1BPU) and Con Wassilieff (ZL2AFP) in 2014. It targets **low-power, low-noise HF chat** with two distinguishing features: **selective calling** (your station only responds to its own callsign) and **automatic image / message handling**.

FSQ was specifically built for the **NVIS (Near-Vertical Incidence Skywave)** use case: regional groups, 80m and 40m at night, low-power transceivers, low-noise rural antennas. It works at signal levels typical of those conditions — moderate, not at the noise floor — and pairs well with QRP operation.

The mode has a small but enthusiastic global community, with daily activity on 7.105 MHz and 3.580 MHz. Operators leave their stations on all evening; FSQ's selective-call feature means they're only "interrupted" when someone explicitly calls them.

## How it works

| Property | Value |
|----------|-------|
| Modulation | 33-tone MFSK ("IFK" — Incremental Frequency Keying) |
| Tone spacing | Variable per symbol — encodes character info |
| Bandwidth | ~330 Hz |
| Symbol rates | 2, 3, 4.5, or 6 baud (FSQ2 / FSQ3 / FSQ4.5 / FSQ6) |
| Typing speed | ~30 WPM (FSQ4.5, the default) |
| Character set | Full 8-bit ASCII + alerts + images |
| FEC | None — but uses **differential encoding** and check digits |
| Selective call | Yes — built into the protocol |
| Image support | Yes — small thumbnail BMPs |

**Incremental Frequency Keying (IFK)**: rather than each tone representing a fixed character, FSQ encodes characters as **differences between successive tones**. The receiver tracks the tone-to-tone *change*, not the absolute frequency. This makes FSQ robust against slow frequency drift — your rig's oscillator can drift 50 Hz over a QSO with no effect on decode. It also makes FSQ inherently sideband-agnostic (USB and LSB decode identically once the mode is locked).

The tone alphabet of 33 covers all printable ASCII characters plus a handful of control codes (selective-call addressing, image start/stop, message delimiters). Each transmitted character changes the tone by a unique increment in the range 1–32 tone steps (modulo 33).

> **Advanced —** FSQ's selective-call ("DirectedCall") protocol works at the message layer above the modem. Each transmission begins with a **destination callsign + trigger character** (e.g. `K1ABC?` to ping K1ABC and ask if active, `K1ABC#` to send a message, `K1ABC*` to request a snapshot image). Receivers only display traffic addressed to their own callsign or to all (`ALL?`). This means an FSQ frequency can have a dozen monitoring stations and only the addressed ones get an alert sound — vastly more pleasant than PSK31 where every QSO appears on everyone's screen.

## Why use it

- **Low-power friendly.** 5–10 W is plenty on NVIS paths. Pairs perfectly with battery-powered or solar-powered stations.
- **Selective calling.** Leave the station running; only get alerted when someone calls *you*.
- **Compact.** 330 Hz fits in any SSB filter.
- **Drift-tolerant.** IFK makes FSQ forgiving of warm-up drift on inexpensive rigs.
- **Image transfer.** Send a thumbnail screenshot or station photo at moderate speed (~30 seconds for 100×100 pixels).
- **Quiet on the band.** Because each station only transmits when triggered, FSQ frequencies feel calm — not the constant clatter of a busy PSK31 or RTTY band.

When to skip it: weak-signal DX work (Olivia / FT8 are better), long-haul HF (FSQ is designed for regional NVIS, not DX), and any case where you want a noisy active "chat room" feel.

## Operating

**Software:** **fldigi** (mode → FSQ → FSQCall). The "FSQCall" sub-mode includes the selective-call and message features; plain FSQ is just the modem.

**Calling frequencies (USB dial):**

| Band | FSQ activity |
|------|--------------|
| 80m | 3.588 MHz (evenings, NVIS) |
| 40m | 7.105 MHz (daily, most active) |
| 30m | 10.144 MHz |
| 20m | 14.105 MHz |
| 17m | 18.105 MHz |

FSQ uses LSB on 80/40m by convention (matches voice band convention) and USB above 30m — though IFK makes the choice cosmetic.

**The FSQ "trigger" commands** (sent as suffixes after the destination callsign):

| Suffix | Meaning |
|--------|---------|
| `?` | "Are you there?" Pings the addressed station; returns a presence ACK. |
| `#` | "Send to me" — opens a message session. |
| `*` | "Send image" — requests a snapshot. |
| `;` | "I have a message for you, will send next." |
| `$` | "What's your active mode?" |
| `!` | "I want to relay through you." |

The trigger character is what makes FSQ feel different from other chat modes. Instead of broadcasting `CQ`, you ping individual stations: `K1ABC?` — and if K1ABC is listening, you'll get a `W2DEF DE K1ABC` reply within seconds.

**A typical FSQ exchange:**

```
TX:  K1ABC?
RX:  W2DEF DE K1ABC
TX:  K1ABC# GM JOHN ES TNX FOR PRESENCE = HW UR WX TODAY?
RX:  W2DEF# GM MIKE ES BEAUTIFUL HERE = 22 DEG ES SUNNY HW CPY?
TX:  K1ABC# CPY FB = MY WX RAINY ES 15 DEG = TNX QSO 73
RX:  W2DEF# 73 OM
```

**Power level:** 5–25 W. FSQ's design point is QRP NVIS — high power isn't needed and isn't socially welcome on the small community frequencies.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| No selective-call alert | Callsign not set, or "alert" disabled | In fldigi → Configure → IDs → set callsign; enable FSQ alert sounds |
| Decoder shows random characters | Wrong baud rate variant | Try FSQ2 / FSQ4.5 / FSQ6 — most activity is FSQ4.5 |
| Image transfer never completes | Audio path too noisy for image FEC | Use FSQ2 for slower-but-more-robust images; or accept text-only |
| Calling stations don't reply | Wrong callsign suffix | Use `?` to ping, not `#` (which expects an open session) |
| Other operators say your text is garbled | Drift or noise | FSQ tolerates drift but not noise crashes — try a quieter band |
| QSO partner stopped responding | They timed out — sessions auto-close after ~3 minutes of silence | Re-ping with `?` |
| TX sounds OK but no decodes back | Sideband convention mismatch | Match local convention (LSB 80/40m, USB above) |

## Common mistakes

- **Calling CQ.** FSQ doesn't really use CQ — you ping a specific callsign, or `ALL?` to announce presence. Operators who CQ on FSQ get ignored.
- **Forgetting the suffix character.** `K1ABC` with no suffix is just text; it won't trigger an alert. Always end the callsign with the appropriate trigger.
- **Running QRO.** FSQ's community frowns on high power — the whole point is quiet, courteous chat.
- **Treating FSQ like a busy mode.** FSQ activity is sparse. Drop in, ping a known station, exchange greetings, drop out. It's not a "raghchew for an hour" mode for most operators.
