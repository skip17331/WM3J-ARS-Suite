# APRS — Automatic Packet Reporting System

> **Advanced callout convention:** sections or paragraphs intended for Extra-class / engineering depth are marked with a blockquote starting `> ⚙️ **Advanced —**`. Simple-mode renderers can hide these; advanced-mode renderers show them inline.

## What it is

APRS is a connectionless packet protocol designed by Bob Bruninga (WB4APR) in 1992 for **real-time position reporting and short messaging**. Stations periodically beacon their location, callsign, and any payload data (weather, telemetry, status) over RF; **digipeaters** retransmit beacons further; **IGates** bridge RF traffic to/from the internet (APRS-IS).

The result is a global mesh network: drive across the country, your APRS-equipped HT or mobile rig beacons your position every few minutes, and friends can watch you move on aprs.fi — over RF where it works, over the internet where it doesn't.

APRS is **not** point-to-point — there's no QSO, no acknowledgment per packet, no connection state. It's a fire-and-forget broadcast system that happens to have a globally-coordinated channel and a forwarding network.

## How it works

| Property | Value |
|----------|-------|
| Modulation | Bell 202 AFSK (1200 Hz / 2200 Hz) |
| Baud rate | 1200 baud |
| Packet protocol | AX.25 (Frame Check Sequence, no FEC) |
| Bandwidth | ~3 kHz (fits in standard FM channel) |
| Typical packet length | 50–250 bytes; ~1 second on the air |
| Channel access | Carrier-sense, random delay (CSMA-style) |
| Sync | Each packet has its own preamble; no global time |

**The packet payload format** (TNC2 monitor format):

```
KE5ABC-9>APN382,WIDE1-1,WIDE2-1,qAR,N4XYZ-3:!4019.50N/07458.30W>234/056/A=000312/Mobile from Houston
└────┬───┘ └─┬┘ └──────┬──────────────────┘ │└──────┬─────────┘ │ │ └─────┬──────┘
   from    to       relay path             │   position       │ course/  altitude/
                                            │   (lat/lon)      │  speed   comment
                                          symbol            symbol overlay
```

Key fields:
- **From station + SSID** — `KE5ABC-9` (SSID 9 = mobile)
- **To** — `APN382` (Kenwood TM-D700 model code, NOT a destination call)
- **Relay path** — `WIDE1-1, WIDE2-1` means "one local digipeater, then one wide-area digipeater"
- **Payload** — position symbol + lat/long + course/speed + altitude + comment text

The "destination" field is historically misnamed — it's actually a **client identifier** (model of the radio sending it). All APRS traffic on a given frequency is heard by everyone within range; the protocol uses content-based routing, not address-based.

> ⚙️ **Advanced —** AX.25 frames have a Header (source, destination, path), Information field (the APRS payload above), and a Frame Check Sequence (FCS, 16-bit CRC). The FCS detects but doesn't correct errors — a corrupted packet is dropped. APRS achieves reliability through **redundancy**: most stations beacon every 1–10 minutes, so missing one packet is rarely a problem.

## Why use it

- **Live tracking.** See yourself or others move on a map (aprs.fi, hams' favorite). Useful for SOTA / POTA activations, road trips, mobile contests.
- **Weather data.** Many APRS weather stations beacon every 10 minutes. Aggregated as wxqa.com — citizen weather reporting.
- **Short messaging.** Send a text message from one APRS station to another. Works through the global digi network, including the internet via IGates.
- **No internet required.** Pure RF coverage works in remote areas. Useful for hunting, hiking, radio-direction-finding events.
- **Built into many radios.** Yaesu FTM-300/400 series, Kenwood TM-D74/710, Icom IC-705/9700, Yaesu FT3DR/5DR — APRS is a checkbox feature.

When to skip it: rag-chew (it's not a chat protocol), DXing (1200 baud over FM doesn't go far on RF — you're really using the internet bridge), or when you want to know your packet was received (no per-packet ACK).

## Operating

**Calling frequency (US):**

| Region | Frequency |
|--------|-----------|
| US / Canada | **144.390 MHz** (FM) |
| Europe (Region 1) | 144.800 MHz |
| Australia | 145.175 MHz |
| Argentina | 144.930 MHz |
| Japan | 144.640 / 144.660 MHz |

The 144.390 MHz channel is the universal standard in the Americas. There are also smaller HF APRS networks on 10.151.000 MHz (LSB) using 300 baud, but they're niche.

**SSID conventions** (the suffix on your callsign):

| SSID | Meaning |
|------|---------|
| -0 (or omitted) | Home station |
| -1 | Generic 1 |
| -3 | iGate |
| -5 | Tablet / iPhone |
| -7 | Walking / handheld |
| -9 | Mobile / car |
| -10 | Internet client |
| -11 | Balloon / aircraft |
| -13 | Weather station |

So `K1ABC-9` is mobile in a vehicle; `K1ABC-7` is walking with an HT. By convention you should use the right SSID so others' apps display the right icon.

**Path settings:**

```
WIDE1-1, WIDE2-1     ← typical mobile (1 local digi + 1 wide digi)
WIDE2-2              ← 2 hops via wide-area digis only
WIDE1-1              ← local-only (use for fixed home stations)
```

The "WIDE" path tells digipeaters how many times to retransmit. Excessive paths (`WIDE3-3` etc.) waste channel time and are considered abuse.

**Beacon interval:**

| Activity | Recommended interval |
|----------|---------------------|
| Stationary at home | 30 minutes |
| Walking | 5 minutes |
| Mobile (slow speed) | 1–2 minutes |
| Mobile (highway) | 10–30 seconds |

**SmartBeaconing** is an algorithm built into modern APRS rigs that adjusts beacon interval based on speed and turn rate. Recommended over fixed intervals — sends often when needed, rare when stopped.

**Software:**

- **Mobile / HT:** Yaesu FTM-300/400, Kenwood TM-D710G, FT5DR — APRS is built in.
- **Mobile + computer:** APRSdroid (Android), APRS Pro (iOS) — uses phone's GPS, transmits via paired radio.
- **Home station:** Direwolf (TNC software) + APRSIS32 (Win) / Xastir (Linux) / YAAC (cross-platform).
- **Cloud / map view:** aprs.fi (worldwide map of all APRS traffic).

**Sending a message:**

```
:K1ABC-9  :Hi, where r u? — from K1WX
```

The format is `:DESTCALL :MESSAGE` (note the spaces). Messages get acknowledged with another packet `:K1WX     :ack01` (where `01` is the message ID). If no ACK arrives in 30 seconds, the sender retries up to 5 times.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Beacon not appearing on aprs.fi | Out of range of an iGate; or path is too short | Add WIDE2-1 to path; or check that your area has IGate coverage |
| Beacon appears but with wrong position | GPS not connected | Check radio's GPS status; often a "GPS LOCK" indicator |
| Packets sent but never decoded | Audio levels wrong (too high or too low) | Check TX deviation: should be ~3 kHz for 1200 baud APRS; tune via APRS test transmit |
| Many packets lost; some get through | Channel congestion (channel always busy at 144.39) | Use SmartBeaconing; reduce beacon interval; consider local digi-only path |
| Path uses too many digis (channel spam) | Path setting too aggressive | Use WIDE1-1, WIDE2-1; never WIDE3+ unless in true frontier areas |
| Messages don't reach destination | Destination station not on RF + you're not internet-connected | Use APRS-IS (internet) gateway; or wait for destination to beacon and ACK |
| Audio splatter / IMD on TX | Over-deviation | Adjust radio's TX audio level until deviation is 3 kHz; many radios have a test mode |
| Cannot decode incoming packets | Audio not reaching TNC | Check rig's audio output to TNC; verify TNC's connect status |
| 9600 baud APRS doesn't work on a 1200-only radio | Different modulation requirements | 9600 baud APRS uses direct FSK and requires "9k6" capable radio (most do not without modification) |
| Beacon delayed by minutes after typing message | Channel busy carrier-sense delaying TX | Normal behavior on 144.39 — packet will go out when channel is clear |
