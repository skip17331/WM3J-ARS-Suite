# PSK31

> **Advanced callout convention:** sections or paragraphs intended for Extra-class / engineering depth are marked with a blockquote starting `> ⚙️ **Advanced —**`. Simple-mode renderers can hide these; advanced-mode renderers show them inline.

## What it is

PSK31 is a narrow-band, conversational digital mode designed by Peter Martinez (G3PLX) in 1998. It uses **binary phase-shift keying** to send text at 31 baud — about typing speed — in a 31 Hz channel. Because each signal occupies so little bandwidth, dozens of QSOs can fit inside a single SSB voice channel.

PSK31 is the closest thing in digital modes to a true keyboard-to-keyboard rag chew. Each side types, the other reads. There's no fixed message format like FT8, no shift like RTTY, no slot timing — just continuous text flowing at typing speed. Mostly-clean reception at signal levels well below CW or SSB.

## How it works

| Property | Value |
|----------|-------|
| Modulation | BPSK (or QPSK with FEC) |
| Symbol rate | 31.25 baud |
| Bandwidth | ~31 Hz (occupied) |
| Sync | Differential phase (no carrier reference needed) |
| FEC (BPSK) | None |
| FEC (QPSK) | Convolutional code (rate ½, K=5) |
| Character encoding | **Varicode** (variable-length, like Huffman/Morse) |
| Decoder threshold | ~−10 dB SNR (BPSK), ~−13 dB SNR (QPSK) |
| Clock tolerance | None — sync is per-symbol |

The clever part is **Varicode**. Unlike RTTY's fixed 5-bit Baudot, PSK31 encodes characters with **variable-length** bit sequences — the most-frequent characters (space, e, t) get short codes (e.g. 1, 11, 101); rare characters (z, $, %) get longer codes (10101010). The result: average information per character is about 6.15 bits, so 31 baud delivers roughly 50 WPM of typing.

Each character ends with a **double-zero** (`00`) which never appears inside a character — that's the inter-character separator. The decoder watches for `00` to know when one character ends and the next begins. No start/stop bits needed.

```
Phase:   0  π  0  π  π  0  0  π  π  0  0   ...
                          ↑           ↑
                     end of char   end of char
```

Phase-shift keying flips the carrier's phase by 180° to encode bits. Differential coding means each "bit" is "the phase relative to the previous symbol" — no absolute phase reference required. This is why PSK31 doesn't need clock sync or pre-tuning.

> ⚙️ **Advanced —** PSK31 is bandwidth-efficient because phase-modulation packs more bits per Hz of bandwidth than FSK at the same SNR. The Shannon limit at PSK31's 31 Hz bandwidth and ~−10 dB SNR is roughly 30 bits/sec — PSK31 achieves ~30 bits/sec actual, which is essentially capacity-achieving for that channel. This is rare for a 1998 design.

## Why use it

- **Conversational.** Type, the other operator reads. Type back. Text-chat over RF.
- **Tight bandwidth.** 31 Hz means dozens of simultaneous QSOs fit in a single SSB passband. Unlike FT8 where everyone shares one window of operations, PSK31 stations can each pick a slot a few hundred Hz apart.
- **Multi-QSO capable.** Operators with practice can carry 3–5 simultaneous PSK31 conversations on the same band by just clicking different waterfall positions.
- **Modest power needed.** 5–25 W is typical; 100 W is rude.
- **Better than RTTY for non-contest use.** RTTY assumes contests (short exchanges); PSK31 assumes you want to chat.

When to skip it: contests (where RTTY rules), weak-signal DXing (FT8 wins by 5–10 dB), or any mode that requires a fixed message format. PSK31 has no error correction in BPSK mode — high-bit-rate modes like FT8 will get through where PSK31 would garble.

## Operating

**Software:** fldigi (cross-platform, free, the standard) or Digital Master 780 (HRD). MultiPSK, gMFSK as alternatives.

**US calling frequencies (USB dial):**

| Band | PSK31 calling freq |
|------|---------------------:|
| 80m | 3.580 |
| 40m | 7.070 |
| 30m | 10.140 |
| 20m | 14.070 |
| 17m | 18.100 |
| 15m | 21.070 |
| 12m | 24.920 |
| 10m | 28.120 |
| 6m | 50.290 |

The dial frequency is the USB carrier; the actual PSK31 audio signal is in the audio passband 1000–2500 Hz above the dial. Pick a slot by clicking the waterfall.

**A typical QSO:**

```
TX: CQ CQ CQ DE K1ABC K1ABC K1ABC pse K
RX: K1ABC DE W2DEF W2DEF KN
TX: W2DEF DE K1ABC GA OM TNX FER CALL UR RST 599 = NAME JOHN QTH BOSTON MA = OPERATING TS-590 INTO DIPOLE = HW CPY?  W2DEF DE K1ABC KN
RX: K1ABC DE W2DEF FB JOHN UR RST 559 ALSO = NAME MIKE QTH PHILA PA = RUNNING IC-7300 ON LOOP = WX CLEAR 14 C = K1ABC DE W2DEF KN
... (continues conversationally)
TX: ... 73 ES BCNU AGN OM = W2DEF DE K1ABC SK
```

The QSO can run as long as both operators want — there's no slot constraint. People rag-chew for an hour or more on PSK31.

**Power level:** 25 W is plenty. 100 W is over-driving most antennas given the narrow signal width — the inter-modulation distortion creates "splatter" (extra signals) that bother neighboring PSK31 conversations. **Run only as much power as you need to copy each other** — 5 W often works DX.

**Audio level:** PSK31's narrow bandwidth makes it especially sensitive to ALC compression. The rig's ALC light should be **off** (not just lit). Reduce the audio level until ALC is dark; you'll see a clean signal on a remote SDR.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| Waterfall shows nothing | Audio not reaching software | Check sound device selection in fldigi; verify rig audio output is enabled |
| Waterfall shows broad noise; no signals | Wrong sideband (LSB instead of USB) | Switch to USB; PSK31 convention is USB on all bands |
| Some signals decode, others appear as nonsense | Wrong sideband for those signals (rare — most use USB) | Verify USB; signals truly decoding nonsense have audio problems |
| Decoded text is correct one character, wrong the next | Audio too low — decoder dropping bits | Raise PC audio output until signal is strong on waterfall |
| Splatter / multiple signals when transmitting | ALC compression causing IMD | Reduce audio level until ALC is **off** entirely |
| Cannot answer a station — clicking the waterfall does nothing | Software not configured to use the same audio device | Check fldigi's "Audio" settings — same device for input and output |
| QSO drops and you don't know why | Other station's audio dropped, or fading | Wait 30 seconds; if no response, send a brief query |
| Multiple stations in same waterfall slot | Two stations chose adjacent frequencies | Pick a slot 100 Hz away from existing activity; click on a clear band |
| You can be heard but cannot hear others | Receive audio level wrong | Increase rig RX volume; check fldigi's audio input meter |
| QPSK works but BPSK doesn't | Decoder mode mismatch | Set fldigi to "PSK31" (BPSK) for the typical QSO; QPSK is rare on amateur bands |
