Macro Variables Reference
These placeholders are expanded by the shared MacroVariableEngine at QSO time. Their values come from the live rig + the QSO entry pane in J-Log/J-Digi — not from editable J-Hub fields. The variable list is part of the suite contract; see j-log-engine/MacroVariableEngine.java for the implementation.
PlaceholderSourceDescription
{MYCALL}Station configOperator's own callsign (Station tab → Callsign).
{CALL}QSO entryDX (worked) callsign currently in the entry pane.
{RST}QSO entryRST sent (legacy alias for {RST_S}). Defaults to 599.
{RST_S}QSO entryRST sent. Defaults to 599 when blank.
{RST_R}QSO entryRST received. Defaults to 599 when blank.
{NAME}QSO entryDX operator name. Defaults to OM when blank.
{EXCH}QSO entryContest exchange / notes field.
{SERIAL}LoggerZero-padded serial number, three digits (007).
{NR}LoggerBare serial number (7, no padding).
{FREQ}Live rigRig frequency in MHz, three decimals (14.225). -- if no rig.
{BAND}DerivedBand tag derived from {FREQ} (e.g. 20m).
{MODE}Live rigCurrent operating mode (e.g. USB, CW, FT8).
Unknown placeholders are left untouched in the output, so future variables won't break existing macros. To add a new variable, edit j-log-engine/src/main/java/com/jlog/util/MacroVariableEngine.java and rebuild the engine + every consumer (j-log, j-digi, j-bridge).

Reverse Beacon Network (parallel skimmer-fed feed)
When enabled, J-Hub maintains a second telnet session to telnet.reversebeacon.net:7000. Skimmer-decoded spots flow through the same SPOT broadcast as cluster spots and show up in J-Map and J-Log automatically (tagged source:"RBN" for distinct rendering). Bands and modes here filter the RBN stream only — the regular cluster filter above still controls operator-spotted feeds.

Running J-Map on a second machine?
J-Map can run on a different PC than J-Hub — useful for a wall-mounted display in another room, or for an op position away from the shack PC. On the remote machine, launch J-Map once with the --hub flag pointing at this J-Hub's host or IP. The address is saved in ~/.j-map/settings.json and reused on every launch after that. 
bash j-map.sh --hub your-shack-pc.local --hub-ws-port 8080 --hub-web-port 8081
The remote J-Map subscribes to spots and config from this J-Hub. No second DX cluster connection — the shack PC remains the single source of truth.
